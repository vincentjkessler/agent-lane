# Alpha Metrics

Agent Lane should publish measured workflow evidence rather than unsupported speedup claims.

## Primary measurements

| Metric | Definition |
| --- | --- |
| Task-to-Test | task received → Test Center usable |
| Human Hands-On Time | active human interaction required per task |
| Manual Handoffs Avoided | downloads, installs, launches, navigation/reorientation steps eliminated |
| Tweak-to-Preview | tweak submitted → updated isolated preview usable |
| Test-to-Settlement | Test Center ready → approve/reject/needs-tweak recorded |
| Recovery Success | failed tasks returned to a usable state without manual reconstruction |

## Comparison protocol

For representative tasks, record the same job through:

1. the ordinary AI-assisted workflow without Lane; and
2. the Lane workflow.

Use timestamps and counted human actions. Keep the raw task description and acceptance criteria identical where practical.

Do not convert a small sample into a universal multiplier claim. Publish the observed measurements and sample conditions.
